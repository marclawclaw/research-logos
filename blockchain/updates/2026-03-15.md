### 4. Full Codebase Structure (from GitHub README)

```
logos-blockchain/
├── core/               Core types — blocks, transactions, UTXO notes, proofs
├── consensus/
│   ├── cryptarchia-engine/   Cryptarchia PoS consensus logic
│   └── cryptarchia-sync/     Chain synchronization over libp2p
├── blend/              Blend mix network
│   ├── crypto/         Cryptographic primitives
│   ├── message/        Message types
│   ├── network/        Network layer
│   ├── proofs/         ZK proofs (PoL, PoQ)
│   └── scheduling/     Cover traffic & delay scheduling
├── zk/                 Zero-knowledge proof infrastructure
│   ├── groth16/        Groth16 over BN254 (arkworks)
│   ├── poseidon2/      Poseidon2 hash function
│   ├── circuits/       Circuit prover, verifier, witness generator
│   └── proofs/         PoC, PoL, PoQ, ZK signatures
├── ledger/             UTXO-based ledger & state transitions
├── utxotree/           Persistent UTXO commitment tree
├── mmr/                Merkle Mountain Range (header commitments)
├── kms/                Key Management System (Ed25519, X25519, ZK keys)
├── libp2p/             Networking — QUIC, GossipSub, Kademlia, AutoNAT
├── services/           Overwatch services (chain, blend, wallet, API, …)
├── nodes/node/         Node binary — wires everything together
├── wallet/             Wallet logic (UTXO selection, key management)
├── zone-sdk/           SDK for building zone sequencers & indexers
├── c-bindings/         C-compatible dynamic library + header
├── testnet/            Docker Compose testnets, faucet, L2 demo
└── tests/              Integration & Cucumber BDD tests
```

Key tech stack:
- **Language:** Rust
- **Consensus:** Cryptarchia engine + libp2p sync
- **Networking:** QUIC, GossipSub, Kademlia, AutoNAT (all via libp2p)
- **ZK:** Groth16/BN254 (arkworks), Poseidon2, circuits at v0.4.1
- **Storage:** RocksDB (requires LLVM/Clang)
- **Service framework:** [Overwatch](https://github.com/logos-co/Overwatch) — declarative, composable services with front layer (Overwatch integration) + back layer (business logic)
- **ZK keys:** Ed25519 + X25519 + ZK keys via KMS; PKCS-compliant ZkSign in use

### 5. C Bindings Available
There is a `c-bindings/` directory providing a C-compatible dynamic library + header. This is significant for ecosystem integrations — non-Rust clients (mobile, embedded, other language FFI) can interface with the node.

### 6. zone-sdk for Building on Top
`zone-sdk/` is for building zone sequencers and indexers. This is the primary developer-facing SDK for teams wanting to deploy Sovereign Zones. Worth tracking closely for PoC work.

### 7. L2 Sequencer Archival Demo
`testnet/l2-sequencer-archival-demo/` — a Docker Compose demo with web UI at http://localhost:8200. Good starting point for understanding Zone architecture hands-on.

### 8. Node Architecture Pattern (Overwatch)
Nodes are composed declaratively using the Overwatch framework. Example:

```rust
#[derive_services]
struct MockPoolNode {
    logging: Logger,
    network: NetworkService<Waku>,
    mockpool: MempoolService<WakuAdapter<Tx>, MockPool<TxId, Tx>>,
    http: HttpService<AxumBackend>,
    bridges: HttpBridgeService,
}
```

Static dispatch / generics throughout — compile-time type safety, highly modular. Services are easily swappable.

### 9. ZK Circuit Setup
Circuits are not compiled locally — downloaded via setup script:
```bash
./scripts/setup-logos-blockchain-circuits.sh v0.4.1
# Installed to ~/.logos-blockchain-circuits/ by default
```

### Consensus Comparison — Additional Detail
Cryptarchia's approach to liveness vs safety is explicit and principled:
- Safety-first chains (BFT-style) halt during failures, require known participants + large staking
- Logos chose liveness: network stays up even with 50% dishonest stake; permissionless entry at any stake amount
- Simpler fork choice (longest-chain) vs Ethereum's complex Gasper committee system
